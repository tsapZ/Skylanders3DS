## Trap Team 3DS: CPSID at boot

Azahar's compatibility list rates Trap Team 3DS "Won't boot". The log says why:

    InterpeterFallback reached with pc = 0x0048271c, code = 0xf10c0040

0xF10C0040 is `CPSID f` (ARM mode: mask the fast interrupts). dynarmic translates an ARM-mode CPS by
asking for the interpreter (`arm_CPS` -> `InterpretThisInstruction`), and Azahar has no interpreter
to fall back to: its `InterpreterFallback` is UNREACHABLE, so the emulator stops on the first CPS.

3DS programs run in user mode, where CPS changes nothing (the ARM Architecture Reference Manual: in
User mode CPS is a NOP), and dynarmic already translates the Thumb CPS (`thumb16_CPS`) as nothing.
emulator/apply_cps_nop.py makes the ARM one the same. With it the game runs on to the title logo and
the language screen with nothing else in the log but the usual friend-service stubs (frd:u Logout,
RequestGameAuthentication), which Swap Force and SuperChargers Racing call too.

A candidate for upstream (dynarmic or Azahar), with a test: the fix touches no game-specific code.

## Taps landed 39 px low (tools/azahar_taps.ps1)

A tap on "English" picked "Français" in Swap Force and Trap Team. The window tree while a game runs
(96 dpi): the render widget is 1706 x 658, but the OpenGL surface inside it is a native window of
1722 x 697, placed 8 px left of and 31 px above the widget: exactly one window frame (AdjustWindowRect
of an overlapped window). The picture is drawn at the surface's bottom left in the widget's size
(OpenGL counts from the bottom), so it shows up where it should, but a click is read from the
surface's top, 39 px higher. A real click would be off the same way while the surface has this size.
The tool now posts the point 39 px (the height difference) higher; Swap Force then takes English.

## What the five games ask for, read from the dumps

tools/code_services.py reads a decrypted dump without running it: the services its exheader allows
and, in its program code (the ExeFS .code, decompressed), the ir:USER command headers it loads.

| Game | IR start | Receiving | AutoConnection | Other services |
|---|---|---|---|---|
| Spyro's Adventure | InitializeIrNop | ReceiveIrnop, ReceiveIrnopLarge | 0x000702C0 | - |
| Giants | InitializeIrNopShared | shared memory | 0x000702C0 | - |
| Swap Force | InitializeIrNopShared | shared memory | 0x000702C0 | - |
| Trap Team | InitializeIrNopShared | shared memory | 0x000702C0 | - |
| SuperChargers Racing | InitializeIrNopShared | shared memory | 0x000702C0 | nfc:u, act:u, am:app, nim:aoc, qtm:u |

All five send with SendIrNop, and above 252 bytes with SendIrNopLarge.

**SuperChargers Racing** carries the same IR library as Giants, Swap Force and Trap Team (one block
of wrappers at 0x46474C .. 0x4648E8). So the portal goes the same way there; the game just doesn't
start infrared before its driver select. It may also use nfc:u (the New 3DS reader). The service
name isn't in its code, and its texts are packed (no "PORTAL" in the dump outside the copyright
lines), so the screen that asks for the portal has to be found by playing.

**Spyro's Adventure** uses the older library (wrappers at 0x2017B0 .. 0x201BEC, read with
llvm-objdump from Visual Studio's LLVM, `--triple=armv6k-none-eabi --adjust-vma=0x100000`):

- InitializeIrNop (0x00010182) takes the same parameters as InitializeIrNopShared: buffer sizes,
  packet counts, baud rate and the shared memory handle.
- ReceiveIrnop (0x000F0040) is called with the buffer's size and a static buffer (id 0). It hands
  back two words: the size, and how many packets still wait. The game reads again while that
  number is above zero.
- The caller (0x2125EC) looks at the first byte for the portal's reply letter ('S', 'Z'), so the
  data is the payload without the infrared packet header.
- Above 252 bytes the game uses ReceiveIrnopLarge (0x00100042, a mapped buffer) instead.

Azahar has none of InitializeIrNop, ReceiveIrnop, ReceiveIrnopLarge or SendIrNopLarge (nullptr in
the function table), so Spyro's Adventure can't reach the portal there. That may be the "Bad" in
its compatibility rating. emulator/apply_irnop_patch.py adds the four:

- InitializeIrNop is InitializeIrNopShared plus a mode in which received payloads wait in a queue
  for ReceiveIrnop.
- An empty queue answers NoData.

'Z' isn't a console portal reply; the run will show what the game wants with it.
